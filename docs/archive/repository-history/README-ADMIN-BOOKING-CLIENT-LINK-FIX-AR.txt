إصلاح ربط الحجز الإداري بحساب العميلة — Queens Salon
===================================================

السبب الجذري:
1) الحجز الإداري كان يرسل userId الخاص بموظف/مدير الاستقبال، وليس Firebase UID الخاص بالعميلة.
2) عند اختيار عميلة موجودة، معرّفها الحقيقي في Core D1 لم يكن يُرسل إلى createBooking.
3) بوابة العميلة تقرأ الحجوزات من Core D1 باستخدام العميلة المرتبطة بحساب Firebase؛ لذلك قد يُحفظ الحجز تحت سجل عميلة مكرر بالاسم/الجوال ولا يظهر في حسابها.

الإصلاح:
- الحجز الإداري يرسل clientId الحقيقي للعميلة المختارة.
- userId/clientFirebaseUid أصبحا خاصين بالعميلة فقط.
- createdByUid يحتفظ بمعرّف الموظف الذي أنشأ الحجز.
- Core D1 يعطي أولوية مطلقة للـclientId المختار بدل التخمين بالاسم أو الجوال.
- عند فتح حساب العميلة، Core Worker يصلح تلقائياً الحجوزات القديمة المرتبطة بسجل مكرر له نفس الجوال/البريد، وينقل معها الفاتورة والدفعات والاسترجاعات والنقاط إلى السجل المرتبط بحساب Firebase.

لا توجد Migration جديدة.

التحقق المنفذ:
- npm run test:frontend:core => 37/37 ناجح
- npm run test:core:worker => 53/53 ناجح
- npm run build => ناجح

بعد فك الملف:
1) انشر Core Worker حتى يظهر الحجز الحالي تلقائياً:
   npx wrangler deploy --config .\wrangler.core.jsonc

2) ارفع الواجهة إلى GitHub/Vercel حتى ترتبط الحجوزات الإدارية القادمة مباشرة بالعميلة المختارة.

بعد نشر Core Worker افتح حساب نواف أو حدّث الصفحة. لا يلزم حذف الحجز أو إنشاؤه من جديد؛ أول تحميل لبوابة العميلة ينفذ إصلاح الربط القديم تلقائياً عندما يكون سجل العميل المكرر مطابقاً بالجوال أو البريد ولا يخص Firebase UID آخر.
