إصلاح المعالجة المحاسبية للاسترجاعات — Queens Salon
====================================================

المشكلة السابقة:
- Core Worker كان ينشئ سجل الاسترجاع في جدول refunds.
- وفي الوقت نفسه ينشئ نسخة منه داخل expense_entries كمصروف.
- لذلك ظهر الاسترجاع داخل المصروفات، وكان احتمال خصمه مرتين قائمًا عند احتسابه أيضًا من الإيرادات.

المعالجة الجديدة:
1) الاسترجاع يبقى في جدول refunds كمصدر الحقيقة.
2) الواجهة تعرض الاسترجاع كحركة إيراد سالبة (Contra-revenue).
3) الاسترجاع لا يظهر داخل المصروفات ولا يدخل في مجموعها.
4) Core Worker يمنع إنشاء مصروف sourceKind/sourceType = refund.
5) صفحة الإيرادات تمنع تعديل/حذف الاسترجاع كدخل عادي، وتوجه إدارته من صفحة الحجوزات حتى تبقى الفاتورة والمدفوعات متطابقة.
6) Migration رقم 0009 تحذف سجلات المصروفات القديمة التي أنشأها منطق الاسترجاع السابق.

النتيجة المحاسبية:
صافي الإيراد = الإيرادات المحصلة - الاسترجاعات
صافي الربح = صافي الإيراد - المصروفات التشغيلية

- Frontend Core tests: 28/28 ناجحة.
- npm run build: ناجح.
